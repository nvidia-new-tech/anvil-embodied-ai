# 本週進度（2026-09）

給還沒接觸過這幾樣新東西的人看：這裡有什麼、為什麼加、怎麼用。

---

## 1. 新工具（`tools/`）

**Benchmark 計分工具**（`tools/benchmark_web/`，用法見 [tools/README.md](../tools/README.md)）：
純 Python 標準庫寫的本機網頁，跟著 `run_inference.sh up` 自動啟動，自動讀出
`.env`/執行中容器所用的 `MODEL_PATH`、`CONFIG_FILE`。固定測試協定：三種包裹
（小黃/小白/大白）各測 10 筆，拆成兩組各 5 筆——隨機放置干擾物 / 無干擾物，
失敗要選原因（approach 深度不夠 / 夾取後翻的不夠高 / 其他）。手臂測試間不回
原點、連續執行。資料存在 `tools/benchmark_web/results/pack.json`（目前只給
flip-pack 任務用，所以叫 pack）。

**Model zoo 盤點工具**（`tools/model_zoo_index.py`）：掃描 `model_zoo/` 底下
每個 checkpoint，列出 policy 類型、訓練步數、action_type、大小；用權重檔案的
hash 抓出內容其實一樣的重複資料夾，以及 `training_state/`、空資料夾這些可以
清掉的東西。

## 2. Model Zoo 整理

- 刪掉一個位元組完全相同的重複資料夾（`pi05-bottle-handover/002000_clean`，
  省了 8.71 GB）
- 刪掉續訓才需要的 `training_state/`（推論用不到，省 0.76 GB）
- 刪掉一個沒有任何權重檔的空資料夾
- 27 個 checkpoint 全部統一命名成 `<run-name>/<步數>/pretrained_model` 格式
  （原本同一批訓練跑出來的東西命名順序會顛倒，肉眼很難確定是不是同一批）

## 3. Benchmark 結果（截至 09-11，flip-pack，SmolVLA）

四個訓練版本、各測 30 筆（3 種包裹 × 10 筆），依總成功率排序：

| 版本 | 總成功率 | 小黃包裹 | 小白包裹 | 大白包裹 | 備註 |
|---|---:|---:|---:|---:|---|
| plus（09-04） | **63%** | 70% | 80% | 40% | 目前最佳 |
| half-plus（09-11） | 37% | 40% | 30% | 40% | |
| combined（09-04） | 33% | 50% | 30% | 20% | |
| flip（baseline，單一任務資料集） | 27% | 20% | 50% | 10% | ⚠ 多數時候需要點 home 才會繼續動作，否則卡在原點附近甩手（OOD）；其餘三個版本沒有這個現象 |

主要失敗原因排序：approach 深度不夠 > 夾取後翻的不夠高。
資料來源：`tools/benchmark_web/results/pack.json`。

## 4. 這次順便修好/發現的 Inference 問題

**`KeyError: 'task'`**：部分 smolvla/pi05 checkpoint 訓練時沒有存
`task_description`，對應的 shape config 又設成 `null`（意思是「跟 checkpoint
拿」），兩邊都空的話 VLA 的 tokenizer 會直接崩潰。目前還有 11 顆 checkpoint
缺這個欄位（清單見 [checkpoint驗收流程.md](checkpoint驗收流程.md)）。

**開起來卡住、畫面沒有任何錯誤訊息**：這是 repo 裡已知但完全靜默的坑——
`multi_process.py` 有算出「還在等哪支 camera / joint state」的原因字串，但
整個程式碼從來沒有把它印出來。排查方式：
```bash
docker exec lerobot-inference ros2 topic list
docker exec lerobot-inference ros2 topic hz /camera/chest/image_raw
docker exec lerobot-inference ros2 topic hz /camera/wrist_l/image_raw
docker exec lerobot-inference ros2 topic hz /camera/wrist_r/image_raw
docker exec lerobot-inference ros2 topic hz /joint_states
```
哪支沒有印出 Hz 數字，就是缺的那支。也可以用 `--echo-topic-only` 先確認 DDS
連線本身沒問題，排除是模型端的問題。

詳細背景與更正過的文件說明見 [checkpoint驗收流程.md](checkpoint驗收流程.md)
和 [執行推論.md](執行推論.md)。

## 5. `run_inference.sh` 新增的旗標

| 旗標 | 作用 |
|---|---|
| `--no-benchmark` | `up` 時不要自動啟動 benchmark 計分網頁 |
| `--dev-src`（既有功能，這次補齊 `docker-compose.devsrc.yml` 進版控） | 用工作目錄裡的 `ros2/src` 蓋掉映像檔內建版本，不用重建 image |

環境變數新增 `BENCHMARK_PORT`（預設 8777），可以改 benchmark 網頁的 port。

**`--dev-src` 測試備註**：解除安全協定（依照官方建議的方式）之後，用
`--dev-src` 跑起來的動作明顯比較確實——先前疑似是安全限制把動作幅度/速度
壓得太保守，導致執行看起來猶豫、不夠確實。**這只是權宜之計**：等這批改動
重新 `docker compose build` 烤進 image，就不再需要 `--dev-src` 了。
