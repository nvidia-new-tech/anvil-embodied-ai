# 安裝指南 —— 在新機器上跑 inference

給負責安裝的人看的。寫於 2026-09-11，來自 `/srv/anvil/anvil-embodied-ai`
的 `single-pc-inference-fixes` 分支（`c04a384`）。

## USB 隨身碟裡有什麼

| 路徑 | 內容 | 為什麼放在這裡 |
|---|---|---|
| `anvil-handoff/lerobot-inference-latest.tar.gz` | 4.8G —— `ghcr.io/anvil-robotics/lerobot-inference:latest` 的 `docker save`，image id `sha256:70fbd34b…` | **只在本機建置過，從沒 push 到 ghcr。** 對這個 tag 跑 `docker manifest inspect` 會回傳 `denied`，所以 `docker compose pull` 不會有用。這個 tarball 是唯一的副本。 |
| `smolvla_flip_pack_20260904_plus_005000/`（在隨身碟根目錄，不在 `anvil-handoff/` 底下） | 865M 的 SmolVLA checkpoint | 已驗證跟來源機器上的檔案位元一致 —— `model.safetensors` 的 md5 是 `f1d4d91ee1d6afd8fb3cd33305cf24b1`。 |

其他東西——repo、HuggingFace cache——都是可以重新下載的，所以刻意
**沒有**複製過來。不用在隨身碟上找。

## 步驟

### 1. 主機前置需求

Docker Engine + compose plugin，加上 NVIDIA container toolkit ——
`docker-compose.yml` 要求 `driver: nvidia, count: all`，沒有這個
整套服務起不來。

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER          # 登出再登入一次

sudo apt install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi
```

NVIDIA 的**驅動程式**必須先裝在主機上；toolkit 只是負責把它暴露出來。
不需要主機端裝 CUDA toolkit——那個已經包在 image 裡了。

**裝 `irqbalance`。** 沒裝的話，多支 USB 相機的中斷預設全部集中在同一個 CPU
核心上處理，負載一高就容易掉幀。`irqbalance` 會把這些中斷自動分散到不同的
CPU threads：

```bash
sudo apt install -y irqbalance
sudo systemctl enable --now irqbalance
```

### 2. 載入 image

```bash
gunzip -c /media/<user>/U/anvil-handoff/lerobot-inference-latest.tar.gz | docker load
docker images ghcr.io/anvil-robotics/lerobot-inference
```

確認 id 是 `70fbd34b…`。不要跑 `docker compose pull`——它會失敗並顯示
`denied`，會讓你誤以為是 image 不見了。

改成重新 build 也是一個可行的備案（`docker compose build`，大約 15
分鐘、需要網路）——但要先看下面關於 `LEROBOT_EXTRAS` 的警告。

### 3. Clone repo

```bash
git clone https://github.com/anvil-robotics/anvil-embodied-ai.git
cd anvil-embodied-ai
```

`configs/lerobot_control/shapes/` 從 2026-09-11 起**已經**進了 git ——
不用另外複製。如果 `ls configs/lerobot_control/shapes/` 是空的，代表你在
一個舊的 commit 上。

`uv sync --all-packages` 不是必要的——容器自己帶了 Python。但還是建議
做一下，因為第 6 步的 preflight 腳本是在 host 上跑的。

### 4. 把 checkpoint 從隨身碟複製出來

```bash
mkdir -p ~/model_zoo
cp -r /media/<user>/U/smolvla_flip_pack_20260904_plus_005000 ~/model_zoo/
```

### 5. 寫 `.env`

`.env` 被 gitignore 排除（`.gitignore:114`），所以 clone 不會帶著它，
隨身碟上也沒有。從範本建立：

```bash
cp .env.example .env
```

然後設定以下內容——這些是來源機器實際使用的值：

```
MODEL_PATH=/home/<user>/model_zoo/smolvla_flip_pack_20260904_plus_005000
CONFIG_FILE=./configs/lerobot_control/shapes/1arm_2cam.yaml
HF_CACHE=/home/<user>/.cache/huggingface
LEROBOT_EXTRAS=pi,smolvla
HF_HUB_OFFLINE=1
ROS_DOMAIN_ID=0
RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
CYCLONEDDS_URI=file:///workspace/configs/cyclonedds/single_pc.xml
```

這個 checkpoint 是 smolvla、單手臂 8-DOF、2 支相機（chest + wrist_r）、
絕對動作——所以用 `1arm_2cam.yaml`。**config 要對應 checkpoint 的
shape，不是它的任務。**

### 6. 把 HuggingFace cache 準備好

SmolVLA 執行期需要載入 SmolVLM2 的 tokenizer，這一步是必要的（ACT
和 Diffusion 不需要）。在來源機器上，cache 裡有
`HuggingFaceTB/SmolVLM2-500M-Video-Instruct`（2.7G）和
`lerobot/smolvla_base`（1.2G）。

第一次跑的時候把 `HF_HUB_OFFLINE=`（設成空字串）讓它能下載，下載完、
cache 熱了之後再改回 `1`。如果 cache 是空的卻把它設成 `1`，會卡住卡得
很難懂，而不是乾脆地報錯。

> 如果你是手動把 HF cache 從別台機器複製過來的，不要複製到 exFAT 上。
> Cache 會用 symlink 把 `snapshots/` 指到 `blobs/`，exFAT 沒辦法存
> symlink——這也是為什麼它沒有放在隨身碟上。要複製的話用 `tar`，
> 或是用 `cp -rL` 把 symlink 解開成實體檔案。

### 7. 上電之前先跑 preflight

```bash
uv run scripts/preflight_checkpoint.py "$MODEL_PATH" --config "$CONFIG_FILE"
```

**Exit code 1 代表不要啟動。** 這件事比聽起來重要：checkpoint 跟 config
之間每一種對不上的方式都會**靜默失敗**——不會 raise、不會警告，手臂還是
會做出看起來合理的動作。舉例來說，config 沒列出 checkpoint 宣告過的相機，
就會被補上一張全 -1 的空白影像、mask 為 0，policy 的動作會慢慢退化成
一個接近固定的姿勢。完整的失敗模式表格在 `docs/執行推論.md` 裡。

單獨驗證 DDS，不需要 GPU 或模型：

```bash
./scripts/run_inference.sh --echo-topic-only up
```

### 8. 執行

```bash
./scripts/run_inference.sh up --build          # 正式環境
./scripts/run_inference.sh --monitor-enable up # + 每一步的 CSV/PNG 報告
./scripts/run_inference.sh --fake-hardware --monitor-enable up   # 不用機器人
```

第一次真實運行時記得加 `--monitor-enable`。

## 全新機器特有的陷阱

**`LEROBOT_EXTRAS` 是在 build image 時就烤進某一層裡的**，不是執行期
才安裝的。這個 tarball 是用 `pi,smolvla` build 出來的。如果用不同的
值重新 build，那些 policy 就會靜靜地不存在。改了這個值之後一定要重新
build image。

**`MODEL_PATH` 必須是絕對路徑，或是用 `./` 開頭。** 一個裸的相對路徑
會被 Docker 當成一個 *named volume*，掛載出來是空的——而且不會報錯。

**`HF_CACHE` 需要寫入權限**，不只是讀取——HuggingFace 載入 tokenizer
時會建立 lock 檔案。

**DDS 的三項設定必須跟 anvil-loader 一致**——`ROS_DOMAIN_ID`、
`RMW_IMPLEMENTATION`、`CYCLONEDDS_URI`。如果一邊用 Fast DDS、一邊用
CycloneDDS，會完全找不到對方，而且只會靜靜地沒有訊息，不會報錯。如果
這台機器是 GPU PC、機器人在另一台機器上，要換成 `two_pc_gpu.xml`，
並在 anvil-loader 那端設定 `CYCLONEDDS_PEER_IP=<gpu_pc_ip>`。

**`network_mode: host` + `privileged: true`** 代表如果主機防火牆擋掉了
DDS 的 multicast（udp 7400–7500），會讓探索機制悄悄壞掉，不會有任何
訊息。

**`DISPLAY` 有被透傳進去**，是給 X11 用的。如果是無頭主機，讓它保持
未設定就好，不要指向一個無效的值。

## 建議的後續動作

把 image push 到 ghcr，這樣下一台機器就完全不需要用隨身碟：

```bash
echo $GITHUB_PAT | docker login ghcr.io -u <gh-user> --password-stdin
docker push ghcr.io/anvil-robotics/lerobot-inference:latest
```

PAT 需要 `write:packages` 權限。用 extras 來命名 tag（例如
`:pi-smolvla`），不要都依賴 `latest`，因為前面提到的「extras 被烤進
image 裡」的問題。

不要把 image 放進 git——GitHub 拒絕超過 100MB 的檔案，而且用 LFS
的話，每次重新 build 都會多存一份 4.8GB 的 blob，永遠留著。Dockerfile
和 compose 檔案已經有進版控，那些才是真正該進 git 的部分。
